# 思维链与正则系统方案（可发布化第一批）

## 一、为什么做

恩熙 2026-09-22 定调：星绥通讯将来可能发布给别的用户使用，功能不能写死在代码里，要做成用户自己能配的设置。第一批照参考项目（Float 小手机，`d:\stellasei-bao\stellasei-bao项目备份\ai-virtual-phone_20260911_155529`）补两套能力：

1. **思维链**：思考型模型（DeepSeek-R1 等）会把思考过程单独传回来——接住、跟着消息存、气泡上可展开看。
2. **正则脚本**：用户自建「自动查找替换」规则（酒馆式），在消息流转的几个环节自动执行。

## 二、勘察结论

### 参考项目（怎么做的）

**思维链**：SSE 逐段读 `delta.reasoning_content` → `onReasoningDelta` 回调透传（`lib/chat-engine.ts` L738-742、L827-836）；非流式 `extractLLMContent` 单独返回 reasoning（`lib/api-helpers.ts` L361-411）；存储 `thinkingText`/`reasoningText` 跟消息走（`lib/chat-offline-storage.ts` L8-18）；展示层按会话隐藏开关（`components/chat-reasoning-visibility-controller.tsx`）。另有「标签解析」模式（从正文抠 `<thinking>` 标签）是可选预设——**v1 不搬**。

**正则**：`RegexRule` 类型（`lib/settings-types.ts` L121-142，placement 1=用户输入/2=AI输出/3=斜杠命令/5=世界书/6=思维链，另有 markdownOnly/promptOnly/trimStrings/深度等）；引擎 `runRegexRule`/`applyRegex`（`lib/llm-prompt-assembler.ts` L1415-1522）；AI 输出在生成后、落库前过 placement=2（`lib/chat-engine.ts` L864-867）；UI `components/settings/regex-manager.tsx`（表单＋测试面板 `testRegexRule` L1524-1570）；持久化 `loadRegexes`/`saveRegexes`（`lib/settings-storage.ts` L498-530）；**默认空框架、无内置规则**。

### 我们现状（接在哪）

- `src/lib/chat/chatApi.ts`：流式 `fetchAIStreamReply`（L467 起）已在收 `delta.reasoning_content`/`delta.reasoning`（L492-493 有 reasoning 累积变量）**但用完即丢**；非流式 `parseCompletionReply`（L213-237）只在正文为空时拿 reasoning 兜底。
- `src/types/chat.ts`：`ChatMessage`（L15-68）无思考字段；已有 `apiText`/`errorText`/`diag` 等「附加信息挂在消息上」的先例，`reasoningText` 照此加。
- `src/apps/chat/ChatWindow.tsx` 发送主流程（L932-993）：`fetchAIStreamReply`/`fetchAIReply` → `extractMetaMarkers` → `splitReply` → 逐条落库（`src/lib/settings/chat.ts` 的 `appendMessage`，IndexedDB 整对象落库——新字段自动跟着存）。
- 设置页：`src/components/phone/apps/SettingsApp.tsx`，view 状态机 `"list" | "api" | "api-form" | "storage"`（L217-218），`SettingGroup`/`SettingItem`/`ToggleItem` 组件可复用。

## 三、改法

### A. 思维链（版本 1.4.9）

1. **接收**（`chatApi.ts`）：`fetchAIStreamReply` 与 `fetchAIReply` 各加可选参数 `onReasoning?: (r: string) => void`——流式把已有的 reasoning 累积变量边到边报；非流式把 `parseCompletionReply` 改成 content 与 reasoning 同时取。**现有「正文空用思考兜底」行为原样保留**（记忆浓缩那条路靠它），兜底触发时不另报 reasoning，免得正文与思考重复。返回类型不变（仍是 string），不惊动其他调用方。
2. **存储**（`types/chat.ts`）：`ChatMessage` 加 `reasoningText?: string`，JSDoc 注明「只展示、永不回喂模型」。
3. **挂载**（`ChatWindow.tsx`）：发送流程里用 ref 累积 reasoning，落库时挂在该轮**第一条** TA 气泡上；半途停止也保留已收到的部分。
4. **展示**：带 `reasoningText` 的气泡上方加「思考过程 ▾」小入口，点开／收起（长文限高滚动）。全局开关「显示思维链」放设置里（与「时间感知」同区，实现时找到那个开关的位置照做）；默认开——普通模型没思考内容、入口根本不出现，默认开无副作用。
5. **流式小提示**（能做就做，做不干净就砍）：思考先到、正文未到时，预览区给个「思考中…」轻提示。

### B. 正则脚本（版本 1.4.10 → 1.4.12）

1. **类型**（新文件 `src/types/regex.ts`）：

```ts
interface RegexRule {
  id: string;
  name: string;          // 脚本名
  findRegex: string;     // 查找（正则源码字符串）
  replaceString: string; // 替换成（支持 $1 等捕获组、{{user}}/{{char}}）
  disabled: boolean;
  placement: ("aiOutput" | "aiOutputDisplay" | "userInput")[];
  trimStrings?: string[]; // 每个匹配块里先删掉的串（照参考项目）
}
```

- `aiOutput`＝TA 回复**落库前**改（破坏性，存的就是改后的）；`aiOutputDisplay`＝**只在气泡显示时**改（存档不动）；`userInput`＝我发的话**送给模型前**改（屏幕上仍显示我的原文）。
- 宏只做 `{{user}}`/`{{char}}` 两个（替换成用户名/角色名），查找与替换都支持。
- **刻意不做**（注释里写明防顺手加回）：按对话深度、按角色作用域、tags 分组、思维链位置、提示词/世界书位置、斜杠命令、完整宏引擎。

2. **引擎**（新文件 `src/lib/chat/regexRules.ts`）：
   - `loadRegexRules()`/`saveRegexRules()`：照 `lib/settings` 里最简单的设置模块的存取模式抄（实现时挑一个照做）。
   - `applyRegexRules(text, placement, {userName, charName})`：过滤 enabled＋placement 命中的规则逐条跑，`new RegExp(find, "g")`；**单条 try/catch——坏正则只跳过那条，绝不炸聊天**。
   - `testRegexRule(rule, sample, ctx)` → `{ output, matchCount }`，给测试框用。

3. **UI**（新组件 `src/components/phone/apps/RegexManager.tsx` ＋ `SettingsApp.tsx` 加入口）：
   - 列表页：一条规则一行（名称＋开关＋作用位小标签），点行进编辑；「新建」按钮；导入／导出 JSON（方便用户之间分享规则）。
   - 编辑页：名称／查找正则／替换成／三个作用位开关／测试框（贴一段示例文字→显示替换结果＋命中次数）／删除。
   - 正则实时校验（`new RegExp` 试编译，写错当场标红）；样式照 `SettingsApp` 的 `SettingGroup`/`ToggleItem` 走。
   - `SettingsApp.tsx`：view 加 `"regex"`，列表加一行入口。
   - **默认零规则**（照参考项目）；编辑页占位文案里给示例（如删星号动作 `\*[^*\n]+\*`）。

4. **接线**（`ChatWindow.tsx` 三处）：
   - `userInput`：送进 `fetchAIStreamReply`/`fetchAIReply` 的 `input` 参数先套规则；我的气泡显示原文不动（`apiText` 记送出去的版本，与「发出去＝存下来＝回喂」口径一致）。
   - `aiOutput`：`reply` 一到手（`extractMetaMarkers` 之前）套规则——与参考项目「rawOutput 先过正则」同位。
   - `aiOutputDisplay`：TA 文字气泡渲染处套规则，只影响显示。

### C. 收尾（每版照例）

`npx tsc --noEmit` ＋ `npx eslint`；`APP_VERSION` +1（1.4.9 → 1.4.12）；`AGENTS.md`「当前状态」同步；施工日志逐条追加（含恩熙原话、参考项目对照、回退方式）。

## 四、验证

**我这边（自动）**：每版 tsc/eslint 全绿。

**恩熙手机端**：
- 思维链：文本 API 换思考型模型（如 DeepSeek-R1）聊一轮 → TA 气泡出现「思考过程」入口、点开能看；换回普通模型 → 没有入口；设置里关开关 → 入口消失。
- 正则：建一条「删星号动作」规则 → TA 回复里动作没了、翻旧记录也是干净的；关掉规则 → 恢复；建一条「仅显示」规则 → 屏幕上变了、关规则后旧消息显示还原（证明存档没动）。
