总 纲（恩熙定的，压在所有条目前面）
  1. 小手机的性能永远优先 做任何功能先问一句：会不会让手机变卡、变慢、变占地方？宁可少做、缓做，不拿流畅换花活。
  2. 真实真人永远优先 恩熙原话：这个 AI、这个角色，看起来就像是现实生活中存在的人。TA 会忙、会累、有自己的生活；凡是在「机器味」和「真人味」之间选，永远选真人味。
  3. 节省开销永远优先 能省的省：缓存能命中就命中、请求能少发就少发、模型能便宜就便宜。绝不为了省事多烧一分钱。
风格规矩（恩熙 2026-09-28 点头）

参考只取功能之骨，名字、视觉、文案一律自己长。骨架自己的、结构通用的、皮全新画、字全新写——外部参考的专有名一个不借；交互骨架可学，装饰细节长在自己的设计系统里；提示词与默认文案逐字重写（过恩熙点头）。骨头（真扣费的钱包、生活节奏、三层记忆、面具身份）全长在自己身上，参考只给血肉——做到这四句，没人说得着。

1.2

副 API（幕后活专用接口）

已实现
是什么 第四把钥匙。聊天归聊天，走主文本接口；记忆归总、记忆规整这类「幕后的活」优先走这套副接口——可以给它配一个别的模型（比如更便宜、更快的）。
为什么 这些活不需要文采。副接口配便宜模型，记忆整理的钱就省下来；以后主模型换贵的，这块也不受影响。
细节 副 API 留空（或没打开）时，这些幕后活自动退回主文本接口，并且改走流式——边生成边保活，内容再多也不会因为「等不到回应、生成太久」被中间商掐线。不填它也不坏，还比原来稳。
已有

  • 记忆归总、记忆压缩、朋友圈印象这三处幕后活统一走它

  • 赞 / 评论 / 转发三枚按钮还是占位（点了说「还在做」），互动数据没有存储
  • 你自己发朋友圈——还没有
  • 恩熙口述过的 12 条完整蓝图（双发、信息差、NPC 共友、楼中楼、修改留底、STORY 事件链、转发、隐藏动机、跟随聊天、独立通知、生图联动）——全录在 docs/朋友圈规划.md，逐条标着已有/没有
总纲 恩熙 2026-09-28 带到（只列要做的功能）：「我想做的不是一个想看就去自动生成朋友圈文案、然后看完了也就过去了的那种模块。我希望角色真的会发动态、会删、会改、会嘴硬、会偷偷屏蔽你、会只发给你看、会让朋友来评论、会托朋友带话、会因为你改掉一句话而多想、会记得你删掉过什么、会把聊天里的小事顺手发进朋友圈、也会从朋友圈里的事情重新回到聊天找你。」——「朋友圈不是番外，它本身就是剧情的一部分。」「高互动并不代表刷屏」

  • 会改——改一句话本身是事件：你改你的，他看在眼里、会多想
  • 会嘴硬——动态的语气是他的性格，不是客服腔
  • 会偷偷屏蔽你——有的动态对你不可见（信息差），你可能从别人那儿听说
  • 会只发给你看——反向的：有的动态只有你能看见
  • 会让朋友来评论、会托朋友带话——NPC 共友不只是观众，还是他的传声筒
  • 聊天 → 朋友圈——他会把聊天里的小事顺手发进动态
  • 朋友圈 → 聊天——他也会从朋友圈里的事重新回到聊天找你——双向都是活的
